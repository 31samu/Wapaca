# Desktop background timetable

A local calendar-to-wallpaper Mac app with an embedded editor and automatic calendar checks. It reads a saved TimeEdit ICS feed and produces month and module wallpapers in light and dark, with a self-contained preview that opens in Firefox or another browser.

Open `output/preview.html` to change the module name, inclusive start/end dates, month, appearance, image dimensions, course filter, room labels, and desktop-icon margin. Use the export buttons for PNG, SVG, or a paired Mac export. These edits last for the current preview session. To make defaults persistent, edit `config.local.json`.

The initial images match the detected built-in Retina display: **3024 × 1964 pixels**, displayed at **1512 × 982 points**. The proposed module spans 5 October to 8 November 2026. The month output follows the current date in Europe/Stockholm, September 2026 for the first build.

## Run

Requires Node.js 22.14 or newer. Install dependencies using `npm ci`.

1. Copy `config.example.json` to `config.local.json` and adjust the defaults if needed.
2. Add a `subscriptionUrl` property to `config.local.json`, or set the `CALENDAR_URL` environment variable. Alternatively, place an ICS export at `data/calendar.ics`.
3. Run `npm run refresh` to fetch and validate a new snapshot.
4. Run `npm run build` to regenerate the preview and all four wallpaper images.
5. Run `npm test` for calendar and layout checks. After building, run `npm run test:preview` for preview interactions and the real snapshot checks.

The source URL is not baked into the code or preview. Local settings, snapshots, and output files are excluded from Git. A downloaded calendar can contain personal information; distribute the source code without these generated files unless you intend to share the calendar.

The supplied subscription is already saved in this workspace's ignored `config.local.json`. The setup instructions above are for a fresh checkout.

Expand **Choose events** below the wallpaper to exclude individual events. Excluded events remain in that list so you can include them again. These choices apply to both appearances, the selected view, and browser exports. They persist in the same browser when local storage is available, and otherwise last for the current session. Exclusions use event UIDs so an event stays excluded if its title or time changes. Browser choices do not alter the subscription or the files generated by `npm run build`; for build-time exclusions, add an `excludedEventIds` array to `config.local.json`.

`TIMETABLE_TODAY=2026-09-06 npm run build` reproduces the initial month and current-day marker. The build does not refresh the feed automatically. `data/source.json` records when the snapshot was downloaded.

## Outputs

- `output/preview.html`: self-contained interactive preview, with all matching event details available below the image.
- `output/month-YYYY-MM-light.png` and `-dark.png`: current-month wallpapers.
- `output/module-YYYY-MM-DD-light.png` and `-dark.png`: fixed module wallpapers.
- Matching `.svg` files: scalable images used by the renderer.
- `output/events.json`: normalized source events for inspection.
- `output/validation.json`: counts, dimensions, and any layout warnings.
- `output/module-appearance.json`: light/dark input manifest using wallpapper's appearance format.

## Behavior and limits

The calendar parser uses ICAL.js. It correctly unfolds ICS text, removes trailing display-only TimeEdit IDs, converts UTC times to Stockholm time, and preserves date-only events with exclusive end dates. The supplied snapshot contains 56 events, including 24 tagged with `1DI300`. Each initial view contains 12 course events.

Both views show Monday–Friday only. Every date includes its month abbreviation. The selected month or module dates determine which weeks appear. Every matching event on those displayed weekdays is included, including dates before or after the selected range. Events outside those week rows do not add more weeks. Weekend events are excluded from the wallpaper, preview details, and visible event count. The grid supports up to 12 weeks; dense ranges can require a larger timetable or produce explicit overflow warnings.

Day rows adapt to their busiest cell. The compact layout keeps event text at 14 logical pixels, places rooms beside times when they fit, and uses a shorter header and footer. Empty weeks stay short. The renderer wraps as many title lines as the row can hold before shortening text, then limits crowded weeks only when the complete grid cannot fit. The Worldbuilding range from 31 August to 30 September 2026 fits all 20 events from the current snapshot at 3024 × 1964. Events that cannot fit produce an explicit count. All source details remain available in the preview. Events with a room in their description that differs from the location field get an asterisk and a note.

This prototype accepts concrete UTC events and date-only events. It deliberately rejects recurrence, recurrence exceptions, duplicate UIDs, and floating/named-zone timed events until those cases have proper handling. It does not claim general ICS compatibility yet. Cancelled events are omitted. Course filtering uses exact summary tokens; the preview also offers all events for comparison.

The image renderer is shared by the preview and exports. It writes SVG using escaped text and rasterizes with Sharp. Font wrapping is conservative and based on Arial metrics estimates; check the exported image at its intended display scale when changing layout or fonts. Browser PNG export uses the browser's SVG rendering, which can differ slightly from Sharp's text rendering.

The preview and regular build do not change the wallpaper. **Export PNG** downloads the selected appearance. **Export HEIC** prepares both appearances as a `.timetable` transfer file; opening that download in Timetable Wallpaper presents the final `.heic` save dialog. The Mac companion applies a wallpaper only when you choose Apply wallpaper. The Mac editor includes calendar refresh and an optional launch-at-login setting. See [PLAN.md](PLAN.md).

## Source layout

- `src/calendar.mjs`: ICS parsing and normalization.
- `src/layout.mjs`: date ranges, grid layout, text wrapping, SVG generation.
- `src/preview.html`: local preview controls and export UI.
- `scripts/fetch.mjs`: explicit feed download with validation before replacement.
- `scripts/build.mjs`: preview and image generation.
- `test/`: date, data, layout, and preview interaction checks.

Calendar and output assets remain local. There are no runtime CDN assets or calendar uploads.

## Mac companion (step 2)

1. Build with `npm run build:native` (requires macOS and Xcode Command Line Tools).
2. Reload `output/preview.html`, choose your layout and events, then click **Export HEIC**.
3. Open the downloaded `.timetable` file with `output/Timetable Wallpaper.app`, then choose where to save the paired HEIC.
4. Review both images, select your display, and click **Apply wallpaper**. macOS controls light/dark switching; the app does not need to stay open.
5. Use **Restore previous** to restore the wallpaper and scaling, clipping, and fill settings captured before the first application.

The export contains both rendered PNGs with identical layout/filter settings, even if controls change while export is running. It contains no subscription URL. HEIC conversion uses macOS ImageIO and validates the two frames and their appearance mapping before writing. Invalid exports and mismatched sizes leave existing output files intact.

The prototype keeps recovery records and unique applied HEIC copies beside the app, under `output/`. Keep that folder available; moving the app also changes where it looks for recovery records. It preserves the original backup across repeated applications until restoration succeeds. Old applied images and archived recovery records are retained. Restoring arbitrary Apple dynamic/aerial wallpaper configuration is not guaranteed; restoration was tested with the existing static PNG.

Ready-made examples: `output/worldbuilding.heic` and `output/module-2026-10-05.heic`. These use the generated sample layouts; export from the preview to carry your current individual exclusions into a new file.

The executable also supports:

```sh
"output/Timetable Wallpaper.app/Contents/MacOS/TimetableWallpaper" encode LIGHT.png DARK.png OUTPUT.heic
"output/Timetable Wallpaper.app/Contents/MacOS/TimetableWallpaper" import EXPORT.timetable OUTPUT.heic
"output/Timetable Wallpaper.app/Contents/MacOS/TimetableWallpaper" inspect OUTPUT.heic
npm run test:native
```

Verified on macOS 26.6.2 with the built-in Retina display: two 3024 × 1964 frames, appearance metadata, macOS Automatic recognition, light/dark selection observed in Wallpaper settings after changing system appearance, applying a different module, and restoration of the original PNG. The original Auto appearance setting and wallpaper were restored after testing. HEIC round-trip tests compare decoded frames with the originals and check rejection of malformed exports and mismatched images. HEIC is compressed, so decoded pixels need not be identical.

Only the current Space was tested, with macOS **Show on all Spaces** off. Inactive Spaces, external displays, reconnection, and other macOS versions remain unverified. No global Space setting is changed. The app is locally ad-hoc signed, not packaged or notarized for distribution.

## Integrated Mac editor (step 3)

Open `output/Timetable Wallpaper.app`. The editor, event selection, Apply action, and PNG/HEIC exports live in one window. The embedded **Export HEIC** button writes the paired light/dark file directly; the separate browser preview uses a `.timetable` transfer file for macOS to finish.

- **Refresh every** offers 15 or 30 minutes, 1, 3, 6, 12, or 24 hours. The choice is saved. **Save & refresh** saves the HTTPS subscription and performs an immediate check, even if the next scheduled check is later. Changes of subscription clear the old HTTP validators.
- Changes to module name/dates, month, image size, course/all-events filter, optional title, rooms, icon margin, and event exclusions save automatically in the Mac app. The title starts hidden. Browser settings and Mac settings are separate.
- The single **Apply wallpaper** button above the editor renders both appearances and sends the paired HEIC to the selected display. **Update automatically while running** also applies changes after edits, refresh, and the local date changes. It skips identical output. Event exclusions use TimeEdit event IDs and survive refreshes; an event appears again only if TimeEdit replaces it with a new ID.
- **Restore previous** restores the saved wallpaper and pauses automatic wallpaper changes. A missing old image no longer blocks Apply. When an unavailable backup exists and the current image is restorable, the old record is archived and a fresh backup is captured.
- **Open at login** uses macOS Service Management. The app reports any required System Settings approval or registration error. This setting starts off; registration and a full login cycle have not been tested on this Mac.
- Closing the window leaves the menu bar app running, which is enough for automatic updates. Use the calendar icon to reopen, refresh, apply, restore, or open an older HEIC/export. **Quit** stops refreshes and wallpaper updates. **Open at login** starts the app again after sign-in.

The native runtime uses URLSession, bundled ICAL.js, WKWebView, and ImageIO. Node is needed for development/builds, not while using the built app. There are no runtime CDN assets. The embedded editor cannot navigate to remote pages or make network requests; the native subscription fetch performs network access.

A timer checks once a minute whether the selected refresh interval is due. The app sends ETag/Last-Modified validators when available, so an unchanged calendar can return without downloading the full feed. Failed requests retry after five minutes. Wake triggers the same due check. New calendar data must parse and render before replacing the saved snapshot. Failures leave the prior calendar and wallpaper in place. At a local date change, the current-day marker updates; a month view following the current month advances into the next month. Historical month selections stay fixed.

`output/app-state.json` stores the subscription, cached calendar, selected display, editor settings, exclusions, and freshness information. The app currently keeps state beside its bundle, so keep the app in this output folder. The bundled seed contains your subscription and initial snapshot. Both are local/private build outputs; do not distribute this app bundle as a generic installer.

Verified: live TimeEdit refresh, cached refresh feedback, reopening from saved data, direct WKWebView-to-HEIC Apply, and restoring the existing HEIC wallpaper. Automated checks cover persistent editor state/exclusions across refresh, invalid calendar retention, paired exports, cache interval parsing, missing previous images, HEIC round-trip quality, and existing calendar/layout behavior. Run `npm run test:editor` and `npm run test:native` after building, alongside the earlier tests. Wake, midnight transitions, launch at login, inactive Spaces, external displays, and display reconnection still need live lifecycle testing.
